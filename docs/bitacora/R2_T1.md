## Simulador
Compuerta: sale con 0 solo si no hay errores HTTP, todas las verificaciones pasan y el p95 de cliente es ≤ 500 ms. Imprime latencia por ruta (p50, p95, máx.).

Contra local (levanta la API real en un proceso aparte con BD temporal; no toca `data/horizontes.sqlite`):
```bash
npm run simular                                   # 40 personas, 4 mesas, polling 2,5 s (~35 s)
npm run simular:golden                            # 20 personas con los votos de tests/golden (prueba sintética)
npm run simular -- --personas 120 --mesas 12      # carga mayor
npm run simular -- --semilla 7 --poll 2500 --json informe.json
```

Contra staging (o cualquier URL), con un admin que ya cambió su clave temporal:
```bash
npm run simular -- --url https://staging-horizontes.estratek.com.co --usuario paola --clave '<clave>'
npm run simular -- --url https://staging-horizontes.estratek.com.co --usuario paola --clave '<clave>' --golden
# o con SUPERADMIN_USUARIO y SUPERADMIN_CLAVE en el entorno, sin --usuario/--clave
```
- Crea una sala "Simulación AAAA-MM-DDTHH:MM" y la deja cerrada (no se borra; se distingue por el nombre). Correos `simN.<codigo>@simulacion.estratek.co`.
- Desde una sola IP: los topes por IP (600 inscripciones/min, 2000 votos/min) dejan correr hasta ~300 personas.
- Staging aún no está arriba (bloqueo de T4: repo remoto y Coolify). En cuanto esté, correr ambos comandos y anotar el p95 aquí.
